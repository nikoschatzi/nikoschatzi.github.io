New Communication Card

Directed the redesign of the WorldFIP slave card around the new NanoFIP FMC, into 400-unit production.
  • Owned hardware and FPGA development of both Motherboard and Daughterboard.
  • Engineered a VHDL FSM for peripheral data transfer to NanoFIP FMC over Wishbone.
  • Resolved 8-byte WorldFIP payload overflow via I2C to the Daughterboard.

Background

CERN's cryogenic control infrastructure relies on WorldFIP communication cards to exchange monitoring and control data with peripheral electronics distributed throughout the cryogenic crates.

More than 1,000 communication cards are already deployed across the LHC, with approximately 300 additional crates required for future infrastructure upgrades. The existing design relied on the MicroFIP ASIC, which became obsolete, requiring a new communication platform.

I led the redesign around CERN's NanoFIP FMC, developing the new communication card from hardware design through FPGA development, validation, and production.

Communication Card Architecture

Each communication card operates as a WorldFIP node and consists of a Motherboard and Daughterboard. Each board contains an FPGA and a NanoFIP FMC, providing the processing and WorldFIP communication interfaces required by the node.

The FPGAs handle the exchange of data with the peripheral crate cards, while the NanoFIP FMC provides the interface to the WorldFIP network. This architecture allows the new card to integrate into the existing cryogenic control infrastructure while replacing the obsolete MicroFIP-based design.

Motherboard & Daughterboard

The Motherboard interfaces with the peripheral cards on one side of the cryogenic crate, while the Daughterboard handles the remaining peripheral cards on the other side. Each FPGA collects and processes the data from its corresponding crate cards.

NanoFIP FMC

The NanoFIP FMC replaces the obsolete MicroFIP module and provides the WorldFIP slave functionality required by the communication card. The FPGA communicates with the NanoFIP FMC through the Wishbone interface.

FPGA & Wishbone Interface

The FPGA is responsible for collecting data from the peripheral crate cards and transferring it to the NanoFIP FMC for transmission over WorldFIP.

I engineered the VHDL state machine responsible for this data path, controlling the transfer between the peripheral-card interface and the NanoFIP FMC through Wishbone.

Peripheral crate cards → FPGA → Wishbone → NanoFIP FMC → WorldFIP

The FSM manages the required read and write operations, providing the hardware interface between the peripheral-card data and the WorldFIP communication layer.

Solving the 120-Byte WorldFIP Payload Constraint

A key constraint was the 120-byte WorldFIP payload limit per node. Due to the crate architecture, the Motherboard handled more peripheral channels than the Daughterboard, causing its data payload to exceed the available WorldFIP allocation by 8 bytes.

This limitation did not exist in the previous design. It emerged from the new communication-card architecture and had to be resolved without changing the existing WorldFIP infrastructure.

I implemented a dedicated I2C link between the Motherboard and Daughterboard FPGAs. The Motherboard FPGA transfers the excess 8 bytes to the Daughterboard, which has available payload capacity.

This allowed the complete dataset to be transmitted within the WorldFIP payload limits while preserving the existing crate architecture and network allocation.

Prototype & Validation

I validated the design at multiple levels, from individual interfaces and FPGA logic to the complete communication chain in a cryogenic test crate.

Signal Integrity & Timing

I used oscilloscope measurements to verify the physical Wishbone signals, including signal integrity, clock quality, and setup/hold timing.

FPGA integrated logic-analysis tools were used to inspect internal state-machine operation and verify the expected data transfers.

System-Level Testing

The complete communication card was installed in a cryogenic test crate together with the relevant peripheral cards.

A dedicated software utility running on the Front-End Computer (FEC) monitored the real-time read/write buffers, allowing the complete data path to be exercised under operational traffic and verifying reliable packet transfer.

Radiation Qualification

The final hardware was subjected to the CHARM 2024 radiation campaign to evaluate its behaviour in the expected radiation environment.

The successful campaign provided the radiation qualification required for deployment in the target CERN infrastructure.

Production

Following prototype validation and qualification, the redesigned communication card progressed into production, with 400 units produced for CERN's cryogenic control infrastructure.

The design provides a long-term replacement for the obsolete MicroFIP-based hardware while maintaining compatibility with the existing WorldFIP infrastructure.

Engineering Summary
